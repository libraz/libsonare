# What this harness is for, and what decides that a change is acceptable

This page is the contract. Everything else under `tools/mastering-eval/` describes a measurement; this one says what the measurements are in service of, and which of them are allowed to decide anything. Where a note, a docstring or a report disagrees with this page, this page is right.

## Scope

**One harness covers both mastering and restoration.** `tools/mastering-eval/` measures the mastering chain (`src/mastering/`) and the restoration modules (`src/mastering/repair/`) with one corpus, one runner and one ledger. There is no second harness for restoration, and one must not be added: two harnesses drift apart on the corpus long before they drift apart on the metrics, and then neither number can be compared with the other.

This is not `tools/eval/`, which aggregates polyphonic F0 accuracy against annotated datasets. Different job, different inputs, no shared code.

## The objective

**A change to a processor is acceptable when it makes the output better by measurement and worse by nothing.** That is the whole criterion, and both halves matter equally. The harness exists because "better" in audio processing is routinely claimed from a single flattering number while a second number, unmeasured, went the other way.

**A metric never says a processor is finished.** It says a change may proceed, or that something regressed. Acceptance of a *sound* is a listening judgement and this harness does not make it.

## The metrics are fixed: two families, four each

Adding a metric later means every recorded baseline is measured against a different set, so the set is closed here.

**Restoration** — measured between the clean reference and the processed output:

| Metric | What it catches | Direction |
|---|---|---|
| Segmental SNR | Residual noise energy, time-localized | higher better |
| Log kurtosis ratio | Musical noise — isolated spectral peaks the processing created | 1.0 means none created |
| STOI | Intelligibility damage | higher better |
| Log-spectral distance | Broadband spectral distortion | lower better |

Log kurtosis ratio is the ratio of the processed output's log-spectral kurtosis to the input's, after Uemura and Saruwatari. It is in the set because segmental SNR improves when a denoiser is made *more* aggressive and musical noise gets *worse* at the same time; the two are read together or neither is read.

**STOI is read on speech-bearing material only.** It correlates short-time envelopes in third-octave bands against a model fitted to and validated on speech; a pure tone carries no such envelope, so the number it returns there is outside the domain the metric was established in and means nothing. Reading it anyway is not conservative — it has already reported a *correct* restoration as a regression on tonal items, which under the pass criterion would reject a good change. The corpus therefore carries speech-bearing items, and every row states whether STOI applies to it. A row where it does not applies the other three, and the absence is recorded rather than filled with a number.

**Mastering** — measured on the chain input and the chain output, and reported as a pair:

| Metric | What it catches |
|---|---|
| Integrated loudness (BS.1770-4) | Level |
| True peak (dBTP) | Inter-sample overshoot past the ceiling |
| Short-term loudness spread | Dynamics — the width of the short-term loudness distribution, not its mean |
| Per-band energy delta | Tonal balance change, band by band |

**ViSQOL is not in the set** — it needs a model file and a runtime this project does not ship. **PESQ cannot be used at all**: ITU-T P.862 is not redistributable and was withdrawn on 2024-01-05.

## The corpus is one corpus

**Synthetic and recorded material, in one directory, generated by one script.** The synthetic half carries defects in known quantity — that is the whole reason it exists, and a generator that plants a defect without recording how much it planted cannot support a detector test.

- Synthetic: sine and chord beds crossed with white noise, pink noise, 50 Hz and 60 Hz hum, clicks, and clipping. **Every planted defect's quantity is written alongside the audio** (click count, hum fundamental and harmonic count, clipped-sample ratio, noise floor in dB).
- Recorded: real captures for the cases synthesis does not reach. **Captures are not committed**, matching the convention the instrument-bank harness already uses; only the generator, the manifest and the metrics land in the tree.

**Restoration currently has mono entry points and the corpus is stereo.** The harness therefore measures both a downmix and the individual channels, and records which it used per run, so that a later stereo entry point can be compared against the same rows rather than against a silently different feed.

## The pass criterion

**No metric may get worse.** A change is accepted when, against the recorded baseline, every metric in the relevant family is equal or better. One regressed metric fails the change regardless of how far the others improved.

**A regression needs no threshold.** The corpus is fixed and the computation is deterministic, so the same input measured twice gives the same number bit for bit. Any worsening is real, however small, and fails the change.

**An improvement does need one, and it is not a measurement floor.** The threshold answers a different question: how much of a measured gain is a property of the processor rather than of the one signal it was measured on. For a defect whose material has a random realization — noise, above all — that is measurable: hold the processing fixed, redraw the defect, and read how far the metric wanders. A gain smaller than that wander was earned by the draw.

Improvement thresholds are therefore recorded per metric in the ledger, set from that measurement rather than from a fraction of how far a deliberate degradation moved the metric. The two are not the same size, and the second is the smaller of the two often enough to be misleading.

**Where the material has no random realization, the threshold stays unset and a different rule applies.** The mastering items are deterministic syntheses; redrawing them is not defined, and their variability lives across *kinds* of programme material instead, which more draws of the same item cannot reach. An improvement there is claimed only when it holds with the same sign on every mastering item in the corpus. Consistency across material stands in for a floor; a number invented in its place would be worse than none.

**A metric may have no resolution for a given knob.** When a change's effect on a metric sits under that metric's threshold, the honest reading is that the metric does not adjudicate that change — not that the change is neutral. Record which metric was silent and decide on the ones that were not.

## The ledger

`tools/mastering-eval/baseline.json` is committed and holds both families in separate sections. A run writes its numbers there; a change that moves them updates the file in the same commit as the code that moved them. A baseline that moved without a behavioural change beside it is a defect in the harness, not a new baseline.

## A metric that cannot fail is not a metric

Before any number from this harness is used to accept a change, each metric must have been shown to go red for a deliberate degradation — and to go red for *its own* degradation rather than for all of them. A set of metrics that all move together is one metric reported four times.

**The case that matters most is the one where nothing should move**: changing only the output gain, leaving the processing identical. If a metric that is supposed to be level-independent moves, it is reading loudness as quality, and every comparison it has ever decided is void.

Which metrics that binds is part of each metric's definition rather than a blanket rule:

- **Level-independent, and a movement is a defect**: log kurtosis ratio, log-spectral distance, short-term loudness spread, per-band energy delta, and **STOI** — which normalizes each short-time band segment against the clean one before correlating, so a global gain cancels exactly rather than approximately.
- **Level-sensitive by construction, and a movement is correct**: segmental SNR. Its reference is the clean signal at the clean signal's own level, so a processor that changes the level has changed the output's fidelity to that reference. Level-matching it first would make it a different metric from the one the literature names. The harness therefore either level-matches before calling it or reads a gain change as damage, and records which it did.
- **Absolute levels, where moving by the applied gain is itself the check**: integrated loudness and true peak. A true peak that did not follow the gain would no longer be in dBTP and could no longer be compared against a ceiling, which is the only thing it is for. The test is that each moves by the gain *exactly*, not that it stays put.

This check is run once, against the metric implementations as they stand, and its results are recorded. It is re-run whenever a metric's implementation changes.

## Restoration metrics exist in two languages, and they must agree

Segmental SNR, log kurtosis ratio and log-spectral distance are implemented in both Python (for the harness) and C++ (for in-tree tests). **One author writes both, and a test pins them to the same value on fixed vectors.** Implemented separately they diverge, and the divergence surfaces as an unexplained difference between a harness run and a unit test months later. STOI lives only on the Python side.

## Dependencies

**The shipped Python wheel's runtime dependencies are not this harness's to grow.** `bindings/python` declares numpy and nothing else at runtime. A metric needing more than that goes into a development extra or carries its own implementation inside the harness; it does not reach the distributed package's dependency list.
