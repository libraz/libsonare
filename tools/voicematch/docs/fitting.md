# Fitting — `autofit.py`

`autofit.py` renders a model candidate, measures it against the selected oracle, and searches the declared calibration space. It is the path that can write values back to the synth source; numerical quality and bank acceptance are separate decisions described in [Acceptance](acceptance.md).

## Fit a voice

Run from the repository root through the uv environment; use `--help` for the complete current option set.

```sh
uv run --locked --project bindings/python python tools/voicematch/autofit.py \
    --spec auto --program 40 --pattern sustain --notes 48,60,72 \
    --optimizer cmaes --max-evals 200 --workers 8 \
    --validate-notes 55,67,79 --dry-run --out fit.json
```

`--spec auto` asks the tuning-enabled library for the program's own catalogue and clamp bounds. A JSON spec is required when the run needs a hand-selected subset or range. `--program` selects the GM program, `--bank` selects a GS variation patch, and `--drum-note` changes the probe to one percussion instrument on channel 10. A variation is its own patch, so its bank belongs in both the render and the catalogue query.

Use `--corpus <capture directory>` and `--corpus-timbre <id>` when a captured grid exists. The corpus supplies the notes, velocities, gate, tails, room, rig, note map, and oracle audio, so fitting and profile comparison share one stimulus. Without a corpus, the probe is generated from `--pattern`, `--notes`, and `--velocities`; the oracle is fluidsynth unless `--oracle-wav`, `--au`, or another explicit source is selected.

The fit must compare the model at the same instrument boundary as the oracle. `rig: baked`, an unclassified rig, and a `rig: none` that rests on no `rig_evidence` on a rig-capable family are refused, as is a `shape fit` or `shape prune` against the same references; a `shape` subcommand that does not fit prints that it is a diagnostic run. `--allow-rigged-oracle` carries a refused reference through as `unverified`: the fit runs and reports, and its values are never written into the source. See [Reference](reference.md#rig-and-room) for the direct, acceptance, and override routes. Room correction may be applied before scoring because a room is measured and convolved, while a rig is nonlinear.

## Knobs and ranges

The tuning catalogue is produced by the library under `SONARE_TUNING_DUMP`; it reports defaults, program-to-patch addresses, field types, and values surviving `clamp_synth_patch`. Use the source to understand a field and the catalogue to know the address the loaded library actually exposes.

| key shape | scope | fit behavior |
|---|---|---|
| `<file>.<constant>` | `SONARE_TUNABLE` engine calibration | runtime override; shared by every patch on that engine |
| `<patch>.<field>` | named program patch | runtime override for every program sharing that patch |
| `famN.<field>` | family fallback patch | runtime override; written back into the family table |
| `dNNN.<field>` | percussion note patch | runtime override for that drum note |
| `gm_fallback_map.<field>` | shared ambience or program-group setting | affects the address group named by the catalogue |

`--program-only` keeps only the selected program or drum note's own patch fields and excludes shared engine constants. Use it for a voice-by-voice write-back pass; adopt a shared knob only when references from more than one voice on that engine hold it. The catalogue's clamp probe must cover shared fields too, but a liveness result from one inactive patch is not evidence that the engine constant is unreachable.

Runtime knobs are set through `SONARE_TUNING_OVERRIDES`, so one tuning library serves the whole runtime-only search. Source knobs use a regex to replace one numeric literal, require exactly one match, and rebuild for every candidate; source-knob searches therefore run with one worker. Both forms may appear in one spec.

Ranges come from the clamp where the field has a meaningful bound. Small normalized intervals, and every field in decibels (`*_db`), are searched linearly over the whole bound; positive time-like ranges are searched around the default in log space; a zero-default field with no useful bound is omitted from `--spec auto` until a hand spec declares how to enable it. Fields left open by the clamp use the documented fallback range or require a hand spec. Integer, selector, count, and boolean fields are exposed through the same override layer and rounded to their declared type. `lfo_rate_hz` is the one field narrowed inside its bound: on a program that names a played instrument (`toneclass.played_vibrato`, everything but the synth and effect slots) it is searched over 3-8 Hz, a player's vibrato rates, while the engine still accepts 0-40 Hz for synth patches.

### Which fields `--spec auto` offers

`knob-classes.json` classifies the fields a search must not treat as ordinary amounts, and `--spec auto` reads it (`knobs.load_knob_classes`). An entry or `reach` pattern that names no key the library reports does not stop the load: it is listed as absent, each run prints one line counting them with their families, and a fit whose knobs include a field such an entry names is refused before its first render, naming the entry and its family (renamed or removed, or only in uncommitted code), so a renamed field cannot lose its class unnoticed. A fit that touches none of them proceeds. `notes` and `pending_landing` are exempt.

| class | `--spec auto` | meaning |
|---|---|---|
| `identity` | never offered | what the instrument is: an enumeration, a count, a geometry |
| `switch` | never offered | a bool, a two-valued field or an integer-valued selector |
| `set_by_measurement` | never offered | placed from measured data |
| `stage_enable` | decided per patch | left out where the patch ships the stage absent (`off_value`, default 0, within `off_within`); where it ships present, the range is cut so it cannot reach the off value |
| `compensating_group` | all members or none | closed by default and listed at start; `--open-group GROUP` offers every member (repeatable), and refuses a group some of whose members this patch or engine lacks |
| `pinned` | never offered | one voice's field (`<patch>.<field>`) held at its `value`, with its `basis` stating the measurement or constraint that pins it; a spec naming it is refused with the key, value and basis, the start-up line prints the voice's pinned entries and flags one whose value the library no longer ships, and a pin is changed by editing the entry |

An engine constant (`<engine>_voice.kName`, the engine one the catalogue reports) is shared by every shipped voice of that engine, and the library does not say which voices consult it. For the engines in `REFUSED_ENGINES` (`brass`, `reed`) the same refusal point refuses a hand spec whose objective (its `--program` / `--drum-note` captures, joint fits included) scores fewer than all of the engine's voices and names one, listing the uncovered voices, and `--spec auto` leaves such constants out and counts them in the by-class line. `--dry-run`, `--diagnose` and `--dump-knobs` write nothing back, so they declare the run a probe and pass. Any other engine's constant on a write-back fit is never refused or dropped: the start-up line warns, and the voices the fit does not score are written to `<out>.unscored_voices.txt` (under `autofit/` in the voicematch scratch root without `--out`) for a regression check after the move.

A field whose 0 is an ordinary value of an always-present stage (a signed detune, a crossfade) is not a stage enable and carries no class. A hand spec may still name a held-out field; it is kept, and a warning at start says the table holds it out of a search. The start-up summary counts what was left out by class. `--dump-knobs` reports `fit_knobs` with the same rules.

The table's `reach` block holds a field out by what the capture's gate can judge rather than by what the field is. Each pattern (same rules as `entries`; one that resolves to no catalogue key fails the load) names the dimensions in `requires`, and `--spec auto` opens the field only where `reference/<capture>_gate.json` holds a bound for every one of them, because a fit may otherwise move it with nothing to hold the result. A field is offered only where a gated dimension can hold what the fit moves; a loss term that reads it is not enough. Three dimensions are required today: `motion` for modulation over time (`lfo*_rate_hz`, `lfo_to_*`, `drift_cents`, `drift_rate_hz`, `*.vibrato_*`, `vocal_voice.kVibratoMaxFrac`, `*.tremolo_*`), `stereo` for interchannel difference (`stereo_spread`, `va.unison_width`) and `damper` for what happens after the key lift (`amp_env.release_ms`), which the held-note dimensions end before; a struck or plucked capture whose key lifts on a note already decayed bounds no `damper`, so its release stays out. `amp_env.sustain` is held out the other way, as a `stage_enable` whose off value is a one-shot: a patch that ships no sustain is not offered one, and a patch that ships one cannot search it down to silence. Only a gate that records `motion` opens the first set (see below), so those fields stay out on every other capture. The gate is the corpus run's capture (`--corpus`), or the capture refit's planner resolves for the program; when none is found the rule applies as if no dimension were gated and the start-up summary says so. The summary counts the left-out knobs by missing dimension under "no gated dimension can judge them", `--dump-knobs` prints the same lines as comments, and a hand spec that names one keeps it and warns. `--spec auto` also leaves out every velocity-axis knob (a field name with a `vel` or `velocity` token, `(^|_)vel(ocity)?(_|$)`, such as `percussion.velocity_exponent` or `mallet_vel_exp`) when no pitch of the probe is sounded at two velocities (`has_velocity_spread`, the condition that refuses `--w-velspan` and the other velocity terms), because nothing in the objective can observe them there and a move would only extrapolate; they stay at their start, the start-up summary counts them (`velocity-axis knob(s) held`), `--dump-knobs` prints them as comments, `--out` records them as `held_velocity_axis`, and a hand spec that names one keeps it and warns. `--hold K,...` leaves the named catalogue keys out of `--spec auto` the same way, at their start, for a refit that holds what a check attributed a fault to; a key the library does not report is refused, a hand spec is refused with it, and `--out` records them as `held_knobs`.

The gate must be able to hold what the fit is allowed to move.

The `motion` dimension is one reading per recording of the pitch motion's depth (cents, peak to peak) and rate (Hz), read from the reference rows' `fm` and compared as the model's depth and rate over the reference's, in doublings, so it has two deltas and none per cell. It is gated only on a recording whose rows record `fm_coherence` and whose median reads as a single source (`metrics_motion.coherence_state`): the correlation of partials 2-6's frequency tracks (deviation over order) with the fundamental's is 1.0 for one source whatever amplitude modulation rides on it, and low for several voices, a baked ensemble or chorus, which a vibrato model cannot reproduce. There are three states, each bound a margin (the scatter of violin's notes) beyond the readings it was set from: at least 0.684 is a single source, at most 0.456 an ensemble, and between them `undecided`, which is not gated and reads "coherence <value> between the single-source and ensemble ranges"; `compare` and the fit's gate audit count the reference rows in each state. The unwarp width ratio (`fm_warp`) is recorded beside it and does not decide, since a real player's vibrato leaves it at 0.5 to 1.0. A recording that is not gated carries its reason, and `compare` prints it as "motion is not gated". The bowed-string, wind and single-voice programs list `motion` among their canonical dimensions (`toneclass._MOTION_PROGRAMS`); choir and the string sections do not.


`switch_candidates` in the table lists float-typed fields whose shipped values across the bank are all integers, for a list to judge; it is regenerated with the table by `knobs.switch_candidates`, and classifies nothing.

Engine constants that have no clamp can still declare a range: `tunable-bounds.json` (`bounds` block) and a `#tunable_bound<TAB>key<TAB>lo<TAB>hi` line in the dump, emitted for a macro that states one. The clamp check labels them `declared range (file)` and `declared range (macro)`, treats a range outside them as ruled out rather than inert, and reports a mismatch when a key has both and they differ (the macro is the one checked). `patch_fields_pending_clamp` in the same file proposes ranges for patch fields `patch_clamp.h` does not carry and is not read.

A best value on either range endpoint is a boundary result, including when the starting value is already there. Widen a hand range or inspect the model before calling it an optimum; a search cannot find a value outside the interval it was given.

`--base-overrides` (an inline `key=value,...` string or `@file`; also on `refit.py`) holds engine constants fixed under every evaluation, for a fit that has to run on constants not yet committed to the source. It is merged into each evaluation's override string with the candidate's keys winning, and `profile.py compare` inherits the same string through `SONARE_TUNING_OVERRIDES`. A base key that a search knob also owns, or that the library does not report, is refused before the first render. The base is part of what the fit answered: `--out` records it as `base_overrides`, `fits.py record` copies it into `fits.json`, and `status.py` reads such a fit as `under_base` (never `current` or `equivalent`) and names the base while any base value differs from what the tree ships, read from `tools/bank-versions.json`. Once every base value is the shipped one, the constants the fit stood on are the tree's own and the fit reads as one with no base; a base key the registry does not carry keeps it `under_base`.

A spec entry's `start` sets where its knob starts, for every kind of knob (a patch field, an engine `tunable`, a `file`/`pattern` literal), clamped into the range with a note; the knob's head stays the shipped value. A key given a start in both the spec and `--start-overrides` is refused. At start-up one line per knob that does not start at HEAD says where its start came from, followed by the count of knobs that do start there, and `--out` records each knob's `start_source` (`head`, `spec` or `start override`).

`--start-overrides` (inline or `@file`; also on `refit.py`) sets where named search knobs start without pinning them. Every key must be a search knob and must not also be a base override; a start outside the knob's range is clamped, with a note. The start is part of the fit's identity: `--out` records `start_overrides` and `fits.json` carries it beside `base_overrides`. The report's start loss, the loss calibration and the `--max-level-drift-db` fence are anchored on the start point, not on HEAD; `level_anchor` names its anchor and, when any start differs from HEAD, adds `head_offset_db`, HEAD's own level read with one extra render (unavailable, with the reason, for a spec with a source knob). The gate audit's pre reading stays HEAD. Write-back, the paste-ready overrides and `refit.py`'s verdict compare against what ships, recorded as `head` on a moved knob.

`refit.py --spec FILE` passes a knob spec to every fit in place of `--spec auto --program-only`; each verdict records the spec path and its knob list.

`refit.py` also reads each voice's `pre.json` before its first fit: a gate dimension already over its bound whose own term (`GATE_OWN_TERMS`, `PERCUSSION_GATE_OWN_TERMS`) has no weight in the fit's profile gets that term raised by the rule a trade's reweighed repeat uses. It prints `[raised from zero weight: ...]` and records `raised_from_zero` and `prefit_weights` in the verdict. A dimension whose measured `abs_median` reading is at least K floors from the reference is raised the same way, with K the bank's p90 of `abs_median` in floors (`floor-units.json`, written by `floor_units.py` from a verification run; the floor is `dimension_floor` under the gate's `reference_spread`). It prints `far: N floors (bank p90 K)`, or `far: N guessed floors (bank p90 K)` when the floor is a guess or the default rather than a measured spread, and the verdict records `raised_far` (the raised terms whose dimension was far) beside `raised_from_zero`. A raise reaches every capture of a joint fit. A weight of 0 given with `--weights` is never raised, red or far. A red dimension with no own term (a proxy-only mapping) is listed as `red_without_own_term`, not raised. An own term the fit's probe refuses for its shape (`DROP_REASONS` in `loss_weights.py`: a velocity term on a probe with one velocity per pitch, `level` with no note/velocity contrast) is not raised either: refit reads the probe's contrasts off the capture cells the fit sounds (`probe_contrasts`), prints `<slug>: <term> not weighted: <reason>` once, and the verdict records it under `prefit_skipped`; a bare autofit reads its own probe and prints the same line. A bare autofit with no gate to read records `no_gate` (the reason) under `prefit`, not `skipped`, which is always the per-term map. `tnr` and `body` are refused the same way when every reference cell of the probe is at the recording's floor or reads the loop. If the fit refuses a raised weight, the voice is fitted plain and the verdict carries `refused`.

Every dimension a fit's gate bounds gets its own term into the loss at a non-zero weight, derived at resolve time from the gate (`reference/<capture>_gate.json` `bounds`, every gate of a joint fit) and the own-term maps `GATE_OWN_TERMS` / `PERCUSSION_GATE_OWN_TERMS` in `loss_weights.py`, which `refit.py` reads too. An own term the resolved profile weighs at 0 or not at all takes the presence weight 0.25; an explicit `--w-<term> 0` wins and is listed as `presence: user zero`. A dimension with no own term (a proxy-only mapping such as `decay` or `attack`, or one in neither map such as `stereo`), or whose own terms the probe cannot measure (a velocity term on a probe with one velocity per pitch), is `unscorable`; refit's verdict judges it after the fit instead. An own term the probe's shape refuses is named once, `presence: <term> not weighted: <reason>`, unless the pre-fit raise of the same run already named it, and `--out` records it under `presence_skipped`. Where the gate bounds a p90 for a dimension, its own term takes its upper tail, whether it is a presence term or one the profile already weighs: the mean of its worst tenth of notes (of pitches for `hfdyn`, `velspan` and `dyn`, each pitch scored on its own rows), or the run's `--loss-tail-fraction` where that is narrower, raised over the mean as the run-wide tail is, so two outlier notes in twenty carry the term rather than a tenth of it. A grid term with no per-pitch reduction keeps its mean and does not cover the p90. The weights are capped at the start point, after the first evaluation and before any other point is scored, so the objective is one fixed function through the search: no presence term may carry more than 10 % of the start's weighted loss, and all of them together no more than 30 %; a binding cap scales the term down first, then every presence term by one common factor, and a joint fit takes each term's smallest weight over its captures. A staged fit caps the final weights, not a stage's. The run prints `presence: N term(s) weighted for gated dimensions (term<-dimension, ...)`, the unscorable list and any cap that bound, and `--out` records under `fit_profile` `presence` (per term: `dimensions`, `weight`, `statistics` the gate bounds, `aggregate` `mean` or `tail`, `tail_fraction`, `covers` the statistics it reaches, and `capped_from` / `cap` `term` or `total` where a cap bound), `unscorable`, and `presence_user_zero`, and beside them `tails` (the same fields for each own term the profile already weighs) and `term_tails` (each tailed term's fraction). `--presence-weights T=W,...` uses a fit's recorded weights as given instead of capping at the run's own start, and `--term-tails T=F,...` its recorded tails; a re-score at a moved start (refit's gain anchor, remote confirmation) passes both, so both points of a comparison are scored by the fit's objective, and a term list that differs from the run's own is refused.

## Search

Coordinate descent (`--optimizer coord`) performs a serial line search per knob and moves a knob only when the search strictly lowers the loss, so a knob the objective cannot see keeps its start value instead of landing on the line search's first probe. CMA-ES (`--optimizer cmaes`) samples correlated candidates and renders up to `--workers` of them at once; a candidate scored alone, which is every coordinate-descent evaluation, is rendered once and has its rows measured over `--workers` processes, with rows identical to a single process's. The render itself is not split: a slot rendered on its own differs from the same slot inside the probe (up to 0.0095 of full scale on the marimba grid), because tails and synth state carry across slots, so the model is measured in the probe's context as the reference is. `--restarts` spends the budget on new starts. `--max-evals` counts candidate evaluations, while a warm cache can reduce the number of fresh renders; `--evals-per-knob K` sets it to `K` times the knob count `--spec auto` resolved, held in [400, 2000]. The cache is keyed by library bytes, harness source, probe, and oracle; `--no-cache` disables it.

Every run that searches prints one line before the first render: knobs, `--max-evals`, evaluations per knob, and the minimum the chosen optimizer needs to move at all. That minimum is 2n+1 for `coord` (the start point and a probe either side of it on every knob, which is also what `--screen` needs), and for `cmaes` the start point plus two generations of its population (`--population`, else 4 + floor(3 ln n)), never below 2n+1. A `--max-evals` under it is refused before any render, for source knobs as well as runtime ones; `--short-run` says the short run is deliberate. `--diagnose`, `--grid` and `--dump-knobs` do not search and are not refused. A run that spends fewer evaluations than the minimum, whether by `--short-run` or by stopping early, is reported as "not a search" rather than "unchanged": its winner is the start point and says nothing about the space. `--out` records `optimizer`, `minimum_evals` and `search` ("search" or "not a search") beside `evals_per_knob` under `search`.

`--screen` probes each range endpoint and drops knobs whose weighted loss change is below `--screen-threshold`. It can miss an effect that exists only in the interior or behind a switch, so check the mechanism, range, and probe before treating a screened knob as inert. `--stages` fits excitation, decay, and then the full objective. `--grid` enumerates a small product of knob values and is useful for interactions; it evaluates the fit objective and is subject to the same reference-boundary rules, so it is not a rig-refusal exemption.

The objective resolves class defaults and explicit `--w-*` overrides, then records each term in its fixed engineering unit. The grid mean and upper tail are both retained for per-note terms, while dynamics, kit relations, and whole-render terms keep their own reducers. Missing reference cells are unavailable; a candidate cell missing where the reference is finite is charged rather than silently removed. See [Measurements](measurements.md) for term definitions, coverage, eligibility, and the percussion measurements.

`harm` weights each partial by its audibility, taken from the louder of the two sides. A partial too bright by d dB therefore costs about twice one too dim by d dB: with equal dB errors the controls read 101.5 against 46.5. A model whose every partial above h1 sits at the floor where the reference has some is charged those partials in full, so silence cannot read as a match.

A pitched capture whose reference median `tnr_db` (over its timbre's rows) is at or under `NOISE_LED_TNR_DB` (6.0 dB, in `autofit_resolve.py`) gets a default `bright` weight, the one the percussion profile gives it (1.0), unless the command line or the spec names one (a 0 included). The start-up output prints `bright weighted: reference tnr X dB ≤ 6 (noise-led trigger)`. The threshold came from the bank's distribution of reference median tnr (28 captures at or under it on 2026-11-13); it is a trigger for a weight, not a classification of the voice, and must not be used to license a noise mechanism. A joint fit triggers only when every capture is at or under it. The trigger lives in the fit-profile resolution, not in the loss modules, so the objective fingerprint does not move.

For percussion, the normal terms include band profile, band decay, tilt, brightness, tonality, strike, ring, density, promptness, and the kit relations named by the capture. `evolve` and `diffuse` are consumed like other measured terms; their windows, shared hit-power reference, validity masks, worst-quarter aggregation, and controls are documented only in [Measurements](measurements.md#percussion-measurements). A pitched percussion reference may remain pitched. `--drum-note` narrows the grid to that note unless `--notes` supplies a family; an explicit kit weight requires a grid covering at least one declared family.

The shape objective is a separate spectrogram path. `shape fit` and `shape prune` accept `--report` for fit, selection, and final-validation records and `--out` for the override set; use it to identify cell-level residuals, not to silently replace the `autofit.py` objective used for write-back.

## Validation

`--validate-notes` and `--validate-velocities` score the selected result on conditions outside the fit grid. Each requested validation value must be disjoint from the corresponding `--notes` or `--velocities`; otherwise the report is training evidence labelled as validation. An external `--oracle-wav` needs `--validate-oracle-wav` for the held-out reference because one WAV cannot supply unseen conditions.

The report distinguishes `search_winner` from `selected`. Inspect `selected.loss`, `selected.quality`, absolute residuals, measurement coverage, target attainment, and the independent validation result before writing anything. A validation refusal may select the defaults even when the search winner improves the training probe. An unavailable validation set is reported as unavailable, not as a pass.

The objective reads a still partial's level as its bare spectral peak (`metrics_note.analyze_note`), while the gate's `balance` reads the power over the partial's lobe ([Measurements](measurements.md)); the two differ by at most about 1.4 dB on a partial within 40 dB of h1, so a fit and its gate can disagree on the stack by that much.

Level balance needs at least two distinct note or velocity conditions with finite reference levels. A single usable condition cannot establish a relative level response; the default weight is dropped and an explicit level weight is refused or reported unknown as appropriate. Held-out quality retains the same coverage requirement.

`--dry-run` restores the pristine source and skips write-back while still producing the report and diff. Use it with `--out` when reviewing selected values. Numerical target attainment is an engineering result; it does not grant listening acceptance or change bank status. Follow [Acceptance](acceptance.md#numerical-quality) for those decisions.

## Fitting against several captures

A patch is often reached by more than one capture: a base voice, a GS variation, a keyoff capture, a struct copy such as the ukulele on the nylon patch. Repeat `--corpus` to fit one set of values against all of them, so a gain on one is not bought blind at another's cost.

```sh
uv run --locked --project bindings/python python tools/voicematch/autofit.py \
    --spec auto --program 24 --program-only --dry-run --out fit.json \
    --corpus <nylon dir> --corpus-timbre grand-227 --corpus-notes 36,60 --corpus-validate-notes 48,72 \
    --corpus <ukulele dir> --corpus-timbre '' --corpus-notes 40,64 --corpus-validate-notes 52,76
```

`--corpus-timbre`, `--corpus-notes`, `--corpus-velocities`, `--corpus-validate-notes` and `--corpus-validate-velocities` are aligned with `--corpus` by position: each is given once per `--corpus` (an empty value for the default) or not at all, and an empty or absent cut falls back to the run-wide flag of the same name. The first capture renders `--program` and `--bank`; every other one renders the program its capture definition names, with the fitted patch's overrides carried across a struct copy (`refit.reach_copies`). One capture is the plain single-capture fit, unchanged.

Each capture keeps its own oracle, room, probe, calibration (its start scores 1.0), drift fences, hold-out partition and hold-out scoring. The joint loss is the mean of the captures' calibrated scores, each counting in proportion to `capture_weight`, plus every capture's own level and sustain fence at full strength, so the start point scores 1.0 and a fence tripped on any capture is paid for. The weight is `min(1, start / JOINT_START_FLOOR_UNITS)`, where `start` is the capture's weighted mean term residual at its start in perceptual units and the floor is the fit-quality target of one unit per term: a capture that starts inside the target has nothing worth chasing, and its ratio against that start would turn measurement noise into loss. That is `loss_i / max(start_i, FLOOR)` with the factor common to all captures taken out. In practice a sibling that is already good cannot dominate the joint, and it cannot be traded away either: the weight only keeps its noise out of the loss, while its own hold-out still refuses the winner if it worsens. The calibrated weights are shared, so a term one capture cannot measure is dropped from the class defaults for all of them and an explicit weight on it is refused. `--raw-loss`, `--diagnose` and `--grid` are refused with several captures.

The record and the report give every capture separately, because the joint can fall while one capture rises. `corpora` lists the captures (id, timbre, program, bank, cuts) and `per_capture` holds, for each, its loss at the start, the search winner and the values kept, its term table in perceptual units, the terms that got worse, its held-out reading and its guard outcome; the report prints one line per capture. The hold-out is scored per capture on its own partition; the winner is refused on the joint hold-out (the same weighted mean), and any capture whose held-out loss rose past 0.005 is named in `validation.worse` and refuses the winner on its own, whatever the joint says, so a gain on one capture never pays for a held-out loss on another. On the train side `per_capture` marks a capture whose own loss at the values kept ends above its start with `worse_than_start: true`, and its output line says so; that is a report line, not a refusal.

The guard stays per capture and any capture tripping it keeps the defaults: a term whose measurements vanished (`measurement_dropout`). `lost_to_start` and the hold-out are joint readings. A single-capture record carries `corpora` as a list of one.

## Fitting without the corpus

`--oracle-cache DIR` lets a fit run on a host that holds no capture audio and no manifest. Where the corpus is present the oracle is measured as usual and its numbers are written to `DIR/<capture>__<timbre or default>__<fit|holdout>.json.gz` (`<capture>` is the `--corpus` directory's name; the hold-out and each capture of a joint fit write a file of their own). Where the manifest is absent, or with `--oracle-cache-only`, the fit reads that file instead. A cache holds the per-note oracle rows, the measured room, the band edge, the channel correlation and a scrubbed descriptor of the corpus (timbre, rate, gate, slot lengths, notes, velocities, classifications; the label and id come from the tracked capture definition). It never holds audio, a spectrogram, an STFT magnitude, a path or anything the manifest says about its source: write and read both pass the content through a whitelist of named keys and refuse an unknown key, a string outside a named id or enum field, and a numeric list longer than 128 entries (256 for a note's `attack_peaks`, one frequency and prominence per isolated peak of its attack spectrum). A row's `fit_tnr_mask` holds only its `fm` and `am` records, five modulation scalars of the kind `tnr_mask` carries. A cache is refused when its identity (capture, timbre, notes, velocities, drum note and gate, mono mode, room flag, role) differs from the run's, when the digest of the measuring code differs from this host's, when the committed reference profile it was read through differs, and, where the corpus is present, when the digest of the manifest and the WAVs it was measured from differs. The multi-scale term compares against the corpus audio, so a cached run is refused while the resolved `mss` weight is above zero (`--w-mss 0` sets it for the noise programs); the report then carries `oracle` (`source: cache` and the cache digest) and, where the class weighed `mss` by default, `scored_without: ["mss"]`. A fit so marked is judged by refit on its `confirm` pair, which scores both points with `mss` on, over `IN_SAMPLE_MARGIN` rather than on the host's held-out notes (recorded as `searched_held_out_gain`), and is kept when that pair does not gain. In `fits.json` it reads `scored_without` until a passing confirm under its own objective is recorded (`confirmed_under`); then it takes the state it would otherwise have and `status.py` names the term as `searched_without`, since a cached search can never include it.

`remote_fit.py run` drives such a fit on a remote build host through sendaway: it writes the oracle caches here, runs `leave_check.py` over the tree and the caches before every sync (failing closed on any audio or array container and on any cache key outside the whitelist), runs the search there with the host's own `BUILD_TUNING` library, and pulls `fit.json`, the per-evaluation log and `host.json` (wall time, exit, the commit the synced tree is, load at start and end, evaluations per second) back. It sends only from a checkout marked by `.cache/remote-fit-tree` that has its own `.sendaway.yml`, because sendaway sends the enclosing project of the working directory; every host line refuses to run anywhere but Linux, because sendaway runs a command locally when the host is unreachable. sendaway stops the host command when the connection drops, so the search keeps its measured candidates in a store on the host (`--cache-dir`, flushed per evaluation) and the driver re-issues it after a drop, with a growing wait, up to six attempts; the restarted search replays what it finished as `stored` lines and renders on from the first evaluation it had not, and `host.json` counts what each attempt replayed and rendered. `run --resume` continues one whose attempts ran out; `pull` collects one that finished while nothing waited for it. An engine listed in `HOST_REFUSED_ENGINES` is refused, for one whose rendering a host's libm moves by more than float noise; `remote_fit.py probe` scores a search's start once there and once here, term by term, and is how an engine is put on or taken off the list. It is empty: every self-sustaining engine (bowed string, reed, brass, flute, free reed, FM) scored its start within 0.5% on the build hosts. `remote_fit.py queue --list FILE` runs a list of searches (one JSON object per line: `slug`, `args`, and any fields to carry into the status) in one host run, `--parallel N` of them at a time sharing `--host-workers` (a coordinate search evaluates one candidate at a time, so its row pool is idle on a one-row grid and parallel searches are what fill the host), and appends one status line per ended search: slug, start and best loss, evaluations, seconds, exit, and the host's Python, NumPy and SciPy versions, which every `fit.log` also opens with. A re-issued queue skips what ended at the same commit with the same arguments. `--host H` routes the tree to a named host through a private sendaway config and a per-host state directory, so runs on two hosts do not wait on each other's lock, and `--host-cap` bounds the workers a host may be given. `run` and `queue` set `--w-mss 0` themselves for a class that weighs `mss` when the arguments give no weight. `remote_fit.py confirm` then scores the search's start and its selection once each here against the audio with the arguments as given, so `mss` is on, and refuses the report when the two machines score the start more than 0.5% apart; a search run without `mss` has its start scored once more here as the host searched it, for that comparison alone. The block records the `objective` it was scored under.

## Diagnosis

`--diagnose` reads the current source and reference instead of fitting or writing. It starts with individual knob endpoints and can add bounded interior, all-low, and all-high joint conditions when active residuals and evidence justify them; the sampled budget is finite and the report records it. A null can reflect an inactive mechanism, a missing cell, a range, or an untested interaction.

Diagnosis separates connectivity from improvement: connectivity is the largest valid measured movement a knob or joint condition produces, while improvement is the largest reduction in the active term on the capped objective the fit minimises. Connectivity reads a cell clipped at the comparison cap at its uncapped distance, so a term already past the cap still shows what moves it; such a term reports `beyond_cap_cells` (the base render's clipped cells) and `beyond_cap_probes`, and its residual is a lower bound rather than a distance near the target. A cell the candidate did not measure has no distance and still leaves the term measurement-limited. Read both after the fit has reached the source state being investigated.

| verdict | interpretation |
|---|---|
| `unreachable` | no valid sampled individual or joint condition moved the term |
| `measurement-limited` | absent or skipped cells, a cap the render cannot read past, or incomplete probe evidence prevent a conclusion |
| `interaction` | a joint condition moved a term that individual samples did not |
| `spent` | sampled knobs move the term but none reduces it; with `beyond_cap_cells` or `beyond_cap_probes` the movement may lie past the cap, where the fit objective cannot see it |
| `partial` / `reachable` | a sampled knob reduces part or most of the gap |
| `unscored` | the term has no weight in this run |
| `matched` | aggregate and reported worst note satisfy the declared numerical unit with known coverage |
| `not computed` | this probe or retained audio cannot compute the term |

`--diagnose` is exempt from the rigged-oracle fit refusal because it reports what the current model and reference contain. Existing unweighted terms can be reported as `unscored`, except `modes` on a class whose default weights do not carry it (every harmonic class): both sides saturate the peak list there, so it is left out of the report unless `--w-modes` names it; an unimplemented measurement axis is invisible to diagnosis. Check measurement coverage and weights before attributing a remaining deficiency to a model mechanism.

## Write-back

Runtime tunables replace their declaration literal, source knobs replace the captured source literal, named patch fields receive or rewrite an explicit assignment in the program table, and `dNNN.` fields land in the drum table. `famN.` values land in the family table: a field set from a `SONARE_TUNABLE` rewrites that constant's default, any other is written as a `t[N].` line. Switch fields are reported rather than written, because a search lands one in a bucket rather than on a value. Values that remain at their starting point are not rewritten.

The fit snapshots target source files, restores them on failure or interruption, and writes only selected values after validation. Selection can retain defaults for measurement dropout or held-out regression. A normalized candidate worse than the start also retains defaults; this ratio guard does not apply under `--raw-loss`. `--out` records search and selected values, losses, validation, quality, source provenance, the objective fingerprint, every point the best-so-far moved through (`path`), and an override string for auditioning without a source edit.

`--spec auto` includes the selected patch fields and the engine constants it exposes. A source write to a shared engine constant can move every program using that engine, while a patch override reaches only the patch name in its key. When fitting a bank grid, use `--program-only` for per-voice fields and inspect the catalogue's patch prefix before deciding that a key was inert.

## Refitting the bank

A finished fit with `--out` also writes `gate_audit` into the record (and a block to stderr): the voice's gates read on the full capture grid at the shipped values and at the winner's overrides, per (key, stat) with its bound, before, after, state and how the objective weighs that dimension (`weighted` when a weighted term reads its own quantity, `proxy` when only a mapped term reading something else is weighted, `unweighted`, with the term named), so a fit that wins by pushing an unscored dimension past its bound (`crossed`, `worse_over`) says so itself; it costs two compares per gate the voice reaches, and is recorded as skipped when the voice has no gate. A flagged `damper` entry names how many of the grid's damper rows were censored (releases that never fell 40 dB), the same count the compare table prints beside `damper`.

A change to the objective leaves every earlier fit answering a question nobody asks any more. [`objective.py`](../objective.py) fingerprints the scoring code (the modules `loss`, `loss_aggregate` and `fit_quality` import, with comments, docstrings and whitespace removed), every `--out` report carries that fingerprint, and [`fits.json`](../fits.json) records per patch which fingerprint its last finished fit answered and whether the values were adopted or kept. `status.py` reads it into each voice's `fit` axis and names a refit as the next action before a listening round when the fit is stale or was never recorded. A behaviour-preserving refactor of the scoring code moves the fingerprint too; that is the conservative direction.

A fingerprint over code text cannot tell a refactor from a change of question, so the record of what was shown not to matter sits beside it rather than inside it: [`equivalence.py`](../equivalence.py) `prove <commit-a> <commit-b>` extracts each commit with `git archive` and runs that tree's own code through two checks, both of which must pass. Re-extraction: `profile.measure` over every shipped capture's cached corpus gives the same profile in both trees, stamps aside (a field only the later tree holds is reported as an addition and is allowed only while everything both hold is byte-identical). Terms: a fixed set of synthetic model/oracle pairs (decaying tones at three notes and two velocities, a vibrato tone, a noisy tone, an inharmonic tone, a percussive hit) gives identical loss terms, key for key and value for value. `--record` appends the pair to [`objective-equivalences.json`](../objective-equivalences.json) only when both pass and the digests differ; the relation is symmetric and transitive. `fits.axis` then reports a fit recorded under an equivalent digest as `equivalent` (naming that digest in `fitted_under`) instead of `stale`, and `status.py` counts the three states apart; an `equivalent` fit does not call for a refit.

[`refit.py`](../refit.py) runs a bank pass. `plan` lists the capitals (`--banks variations` the variations, `--banks kits` every drum note a kit's machine captures hold) whose capture answers at the instrument boundary and has a gate; `run` fits each against its corpus with alternate notes held out (a drum note, held at one velocity by the module, is judged by the gate alone) and compares `profile.py compare --json` before and after the fit's overrides. A fit is adopted when values moved, the held-out notes improved, no gated statistic newly exceeds its bound and the summed excess over the bounds did not grow. A drum note has no held-out notes, so its fit must also gain more than `IN_SAMPLE_MARGIN` (0.005, relative) of the full objective on its own notes (the `confirm` block's local pair when the fit carries one, else the report's own baseline and selected quality), or it is kept (`confirm gain under the floor`; `no in-sample gain to judge` when none can be read); the verdict records `in_sample_gain`, and an adoption on it is recorded `in_sample`, which `status.py` shows as its own fit state, never `current`, until a held-out condition is captured or it is listened to. A fit whose probe could not score level (`level_unscored` in the report: a single condition, so common-gain removal leaves the absolute level arbitrary) has its patch's output gain re-solved after the search, so the model's mean level over the fitted notes (`peak_dbfs` for a kit hit, `held_peak_dbfs` for a pitched note) returns to the shipped one within 0.05 dB in at most four secant renders; the gain is solved afterwards rather than held in the search because drive, envelope, filter and mode levels also move absolute level. The anchored point is kept only when its full-objective loss stays within `IN_SAMPLE_MARGIN` of the candidate's, recorded as `gain_anchor` (`failed` with both losses otherwise), and `in_sample_gain` then reads the anchored loss. A fit may not change what the probe cannot observe: after the anchor, every fitted note is rendered to -60 dB (12 s at most) at the shipped values and at the fit's, and past the end of its scored window (the corpus slot its reference row is read over) the fit's late decay may be no slower than the slower of the shipped model's there and the reference's last observed slope (the last third of its decay above any preroll floor), by 1 dB/s, nor its time to -60 dB more than 10 % longer than the slower of the shipped one and the reference's projected along that slope; a fit that breaks either is kept (`ring past the observed window`), recorded under `tail_check` (`skipped`, blocking nothing, where no value moved). A post-fit check that fails with an error (the gain anchor's level read or rescoring, or the tail check's renders or reference audio) records `error` instead, and the voice is left unjudged: its verdict is `stopped` with the check named (`gain anchor failed: <reason>`, `tail check failed: <reason>`), and the next `run` or `rejudge` runs the check again. `skipped` is kept for a check that does not apply (no gain field, a level within tolerance). It is checked after the fit rather than held in the search because the ring knobs act inside the window too. A fit is also kept when a dimension its objective could not weigh (`fit_profile.unscorable`) reads worse after it than before by more than its floor on any gated statistic (`|post| - |pre|`, the floor as `resolve` takes it below): `unscorable <dim> worsened past its floor (<stat> pre->post, floor f)`, with the rows under `unscorable_worse`. It runs after the tail check and before the trade checks. A single-note fit inside a multi-note gate (a kit note) is also read on its own rows: a kit statistic reduces over every hit, so one note can worsen without moving it. Each kit compare records its per-row deltas (`rows`, kept by capture as `note_rows` in `pre.json` and `post.json`), and a fitted note whose own row reads worse by more than that dimension's floor (`|post| - |pre|`) in a dimension the row's capture gates (one its gate holds a bound for; a row of a dimension that capture excuses is never a reason) is kept (`own row <dim> n<note>v<vel> worsened past its floor`, with the rows under `own_row_worse`); a pre or post recorded before per-row deltas existed is refused rather than read as clean. `resolve` applies the same rule to every path point it accepts, so a point refused only by the note's own row is a `floor` refusal and its rows are listed in `blocking` with `n<note>v<vel>` as the statistic and no bound. refit refuses a judge library built before the newest commit touching `src/midi/synth`, naming the commit and the library's build time, since the rows the fit did not move are then measured on an older bank. Every verdict records `moved_keys`, the knobs the fit moved, for a re-queue to hold with `--hold`. A field the gate cannot judge is held at its shipped value: a typed switch or a count, which a search lands in a bucket of rather than on a number; an envelope sustain crossing silence, which turns a one-shot into a note that rings until a note-off a drum never sends; and a field whose `reach` entry needs a dimension none of the voice's gates bounds, read from the same table and the same gate bounds `--spec auto` uses (a release without a `damper` bound, since nothing after the key lift is read). A fit that improves the held-out notes while newly exceeding a bound, or moving a held field, is a trade: `resolve` bisects the points the search's best-so-far moved through (the report's `path`) for the furthest one the gate accepts (no bound newly over, summed excess not grown, gate load fallen, and no gated statistic worsened by more than its floor; `|pre| - |post|` per statistic, the floor being the gate's own `bounds[dim].floor` when present, a stored 0 included, else `dimension_floor` over its `reference_spread`; a pair its gate holds no bound for has no floor, and asking for one is an error), and failing that refits once with the terms carrying the broken bounds weighed up and searches its path the same way. The objective and the gate measure some dimensions through different windows, which is why weighing a term up does not reliably settle a trade and the path does. `adopt` writes the adopted values into the program, family and drum tables and records every finished fit; a trade `resolve` kept carries `kept_for`: `bound` (no visited point kept every bound), `floor` (the nearest refused point past the accepted one was refused only by statistics worsening past their floor) or `under_floor` (no move worth counting: the accepted point moves no statistic better than its floor, or the nearest point grows no row and worsens none yet its gate load does not fall; the `why` names which). The verdict records that refused point (`refused_point`: eval, cached compare file, newly over rows, rows worse past their floor), so no render is added. `bound` and `floor` are recorded `blocked`, `under_floor` as `kept`; a kept verdict without `kept_for` is refused by `adopt` until `rejudge` and `resolve` settle it again. A `blocked` record lists in `blocking` the rows of that refused point read against `pre.json` (`gate`, `dimension`, `statistic`, `before`, `after`, `bound`, `floor`, and `why`, `bound` for a row over its bound whose excess grew past `pre.json`'s and `floor` for one worsened past its floor), and `status.py` shows it as its own fit state whose next step is the mechanism behind those rows rather than another refit, until a later objective turns it `stale`; an unresolved trade and a stopped voice are not recorded; the `fits.json` entry carries `corpora`, the `{capture, timbre}` list the fit answered, beside `capture` and `timbre`, which stay the first of them. `--joint` fits each melodic voice against every capture its gates name (its own first, then those whose corpus is on the machine and which have notes to hold out; the rest are listed with the reason in `plan`) in one joint fit, each held out on its own alternate notes. A kit is unaffected by it. Without `--joint` a voice is fitted against its own capture alone.

The tuning layer applies a patch's overrides after the program tables have copied it, so an override on a capital never reaches `o.<copy> = o.<capital>;`. Every render repeats each patch-field override on each gate patch that still inherits that field. A field the copy, or a copy between them, assigns by name belongs to the copy. The baseline `pre` is the fit's start: each knob of an existing fit is pinned to its `start`, so a fit started from what ships is judged against what ships. A fit whose start is no longer what ships is refused with the knobs that moved, and is refitted from the shipped start; a recorded `pre` pinned away from what ships is moved to `stale/` and measured again. Each gate patch is also walked back through the git history of `tools/bank-versions.json` and `fits.json`: the trailing run of commits that moved its values while recording a unit of its struct-copy chain is the refit write-backs its shipped values descend from. `pre.json` lists each field of that run owned by the voice's own chain under `descends_from`, with its value before the oldest such commit; nothing there is pinned. An adoption `fits.json` records but `bank-versions.json` does not yet carry is listed as unresolved rather than guessed. `rejudge --only <slugs>` deletes a voice's `pre`, `post`, path renders and verdict, re-measures them over the fits on disk without running a fit, and leaves a trade that needs the reweighed refit open for `resolve`.

Run it in a worktree at a fixed commit: the evaluation cache and the build both follow the tree, so concurrent edits would otherwise change what is measured mid-pass.

## Build and loader isolation

`autofit.py` configures an isolated `--build-dir` with `BUILD_SHARED=ON` and enables `BUILD_TUNING=ON` when runtime knobs need it. Each candidate render runs in a fresh subprocess with `SONARE_LIB_PATH` pointing at that build's dylib, so the override table is read before library initialization and a rebuild cannot reuse an already loaded artifact. `build-python-shared` is refused as the fit build directory because it is the normal shared-library tree.

`--lib <dylib>` fits against a prebuilt `BUILD_TUNING=ON` library instead: nothing is configured, built or written beside it, and a spec with `file`/`pattern` knobs is refused because only runtime overrides can move a prebuilt library. A dirty `src/` is not a refusal there; the sources newer than the dylib are warned about and recorded in `--out` as `library` (path, mtime, sha256, `newer_sources`), and a render under `SONARE_TUNING_DUMP` first proves the library honours overrides. `refit.py --lib` passes it through to every fit and comparison.

Before a runtime search or diagnosis, the harness checks that a whole-spec override changes a render; a single genuinely inert knob remains a diagnosis result, while a flat whole-spec result indicates an unavailable tuning build, an ignored key, a rejected range, or a loader path that did not select the build. The fit records the build and source state in its report.

For recovery, native component observability, identity, liveness, and the exact verification commands, see [Development](development.md).
